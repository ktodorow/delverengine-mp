## 2. Issue #18 — Down, revive, and respawn Participants

### 2.1 Requirements (from the issue)

Host selects 1–5 starting Lives (default 3), locked at campaign start, tracked per slot. Zero health enters a
ten-second Downed state in unpaused session time; the Downed Participant may look but not move, attack, use,
block or ping. A living teammate completes an uninterrupted three-second Revival for 25 % health without Life
loss; movement or damage interrupts it. Bleedout consumes the Life and respawns at the Respawn Point with 50 %
health and cleared temporary effects; the selected hotbar item drops. Disconnecting while Downed does not stop
bleedout. All #38 native statuses/actions must integrate so obsolete attacks and effects never leak into a new Life.

### 2.2 What was built (`7dc94fc`, 22 files, +1309 / −23)

- **`multiplayer/lives/AuthoritativeLives`** (new) — Host-owned per-slot state machine in unpaused Host ticks
  (60/s): `MINIMUM/MAXIMUM/DEFAULT_STARTING_LIVES` 1/5/3, `BLEEDOUT_TICKS` 600, `REVIVAL_TICKS` 180,
  `REVIVAL_HEALTH_PERCENT` 25, `RESPAWN_HEALTH_PERCENT` 50. `Condition {STANDING, DOWNED, EXHAUSTED}`,
  `Outcome`/`OutcomeKind {REVIVED, RESPAWNED, EXHAUSTED}`, `down`, `beginRevival`, `cancelRevival`, `tick`,
  `healthPercent(max, pct)` rounding up to at least 1, revision counter that changes only on transitions.
  **Bleedout holds while a Revival is in progress** (recorded in ADR 0007 and the spec).
- **`multiplayer/lives/DirectConnectLivesController`** (new) — client/Host presentation: `prepare()` sets
  `Player.deathDeferredToAuthority` so zero Host health never reaches native `Player.die`; `update()` tracks
  Lives decreases → `beginNewLife` (Host clears status effects and drunk state, local drops the selected hotbar

- **`DirectConnectHost`** — `startingLives` (`setStartingLives` throws after session start), `advanceLives(hostTick)`

- **Tests** — `AuthoritativeLivesTest` (14 cases: independent slots, bounds, bleedout timing, pause hold, revival

## 3. Issue #19 — Spectate after Life exhaustion and resolve Party Wipes

### 3.1 Requirements (from the issue)

A Participant with no Lives becomes a Spectator who can cycle living Participants' first-person views and chat,
but cannot move, reveal map knowledge, affect the world or ping. Monsters ignore Spectators and Downed
Participants. The Host listen server continues when the Host character spectates. Simultaneous Downing resolves
bleedout immediately and eligible slots respawn together. Party Wipe only when no active Campaign Slot can
return; the defeated campaign enters a terminal state. Switching views never repeats gameplay, leaks personal
knowledge or leaves prior target effects attached.

Owner addition beyond the PRD: **third-person view toggled with left mouse** (2026-09-22 10:10 request).

## 4. Issue #39 — Scatter, damage and reclaim a fallen Participant's items

### 4.1 Requirements (from the issue)

On bleedout consuming a Life, Host scatters the fallen Participant's **backpack and hotbar** at the fall position;
**equipped weapon and armor stay**; **Revival never drops anything**. Drops are unowned #16 physical items. Loss is
decided **once** from the **last damage source**:

| Cause of death | Dropped items |
| --- | --- |
| Melee, arrows, magic missile, poison, drowning | nothing lost; drowning scatters up to 3 tiles |
| Explosion | each item 35 % destroyed; 3 % chance all destroyed; survivors lose 1–3 condition |
| Lava | all destroyed |
| Burning | scrolls and food destroyed; potions 50 % |
| Fall / pit | potions 50 % shattered; weapons and armor −1 condition |
| Spikes / traps | weapons and armor −2 condition |
| Frost / ice | potions 30 % shattered |

Gold: `loss = floor(gold × clamp(8% + 4%·prior losses − 2%·destroyed, 0, 25%))` from the #17 ledger. No
message. Exhausted slot: hidden 6-minute unpaused timer on that slot's drops only; pickup cancels per item; expired
items become consumed tombstones. Host-authoritative, applies to disconnected Downed Participants.

  `getLastDamageCause`; reset in `restoreParticipant`. `NativeCombatAuthority` cause overload with default.

### 4.3 Play-test rounds for #39 (all 2026-09-23)

**Round 1, 13:44 — instant re-death after respawn.** *"It drops all items except the one it is holding … after
respawn it dies immediately, like out of nowhere."* Native health sync compared native hp to the **live** snapshot,
so a respawn restore arriving mid-frame looked like full-health damage and was reported back to Host. Fix: compare
to the last **applied** health:

```java
int applied = actor == attachedPlayer ? lastLocalHealth
        : actor instanceof RemoteAvatar ? ((RemoteAvatar)actor).getAppliedHealth() : -1;
if(applied < 0 || !nativeAuthority.canApplyNativeParticipantEffect(participant)) return;
int amount = applied - Math.max(0, actor.hp);
if(amount == 0) return;
```

The held item survived only by accident; WIELD tracking made it deliberate.

**Round 2, 13:56 — broken worn armour.** *"What if the armour is worn and it is 0 AC … shouldn't he lose his
armour?"* Options offered; owner chose **1**: broken worn or held gear is destroyed on death, not dropped, and does

## 5. Decisions recorded during the session

1. **Lock rule** (from the #18 freeze): never hold the Host monitor together with the
   `AuthoritativeCombatEncounter` monitor in new code; `advanceLives` and `applyLifeLoss` run outside the Host lock.
2. **Bleedout holds during an active Revival** (ADR 0007 / spec update).
3. **Third-person Spectator view** on left mouse is an owner addition beyond PRD #1.
4. **Party Wipe exits the instance** in multiplayer rather than reloading a save; Game Over keeps drawing unfocused.
5. **Host movement mirrors native water physics** (56 % speed, 25-tick ramp, water step height).
6. **No loss summary; hidden 6-minute despawn; equipped and held gear kept; broken worn/held gear destroyed**
   without softening gold (owner option 1).
7. **Gold penalty** `clamp(8% + 4%·prior losses − 2%·destroyed, 0, 25%)`, computed in basis points.
8. **Presented-revision rule** on the client item controller; **applied-health rule** on native health sync.
9. **Template key = class + name + tex**; only catalogued templates spawn across peers.
10. **Dev tools never ship**: only `--dev-tools` / `-PdevTools=true` enables `Game.devToolsEnabled` and
    `Game.isDebugMode`; Direct Connect launches no longer force debug mode.

## 7. Tooling lessons

- CCE MCP server dropped twice; Bash/grep fallback works, reconnects later.
- Integration tests that cross a 10-second bleedout need a custom 14 s wait (default helper times out at 8 s).
- Headless test pitfalls: `Fire.init` needs a renderer (use `setRuntimeSpawned`), `new Missile()` needs
  `StringManager.localizedStrings`, `Player.equip` NPEs headless (pre-hold the item), a test tile with floor 0 and
  default ceiling 0.5 has no headroom for a Player spawn.
- A scripted multi-file edit with a wrong relative path silently skipped the Host/overlay changes once; use absolute
  paths and confirm with a VM build.
- Gradle in the VM: first cold run ~17 min; lock conflicts when the owner's Gradle runs at the same time.
